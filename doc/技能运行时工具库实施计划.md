# 技能运行时工具库实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 创建一个由 uv 管理的 Python 类库，把真实 `SKILL.md` 及其异构 Tool 绑定编译成可供 LangChain Agent 使用的 `SkillBundle`。

**Architecture:** SkillRuntime 从 Repository 读取 Skill 与已解析的 Tool 绑定，由 SkillParser、ToolFactory 和 PromptCompiler 依次完成解析、异构工具适配和提示词编译。四种 Tool 通过统一 ToolAdapter 协议转换为 BaseTool，其中客户端工具由 PendingClientToolTransport 使用 `call_id + asyncio.Future` 等待业务 WebSocket 回传结果。

**Tech Stack:** Python 3.11+、uv、LangChain Core 1.x、LangChain 1.x、Pydantic 2.x、PyYAML、jsonschema、langchain-mcp-adapters、pytest、pytest-asyncio、ruff、mypy。

## Global Constraints

- 所有依赖必须由 uv 管理并提交 `uv.lock`。
- Python 包采用 `src/langchain_skill_runtime` 布局，支持 Python `>=3.11`，本机使用 Python 3.13 验证。
- 项目文档只允许存放在 `doc/`，文档文件使用中文名称。
- 如未来产生 SQL，只能使用中文文件名并存放在 `doc/sql/`；本计划不创建 SQL。
- 核心库不依赖数据库 ORM、Web 框架、模型供应商或具体 WebSocket 实现。
- 核心库禁止使用 `eval` 或 `exec` 执行数据库源码。
- `SKILL.md` 中的 `allowed-tools` 只用于兼容和诊断；真实执行能力以 Skill-Tool 绑定和 ToolDefinition 为准。
- 每个生产行为必须先写失败测试、确认失败原因，再写最小实现并确认通过。
