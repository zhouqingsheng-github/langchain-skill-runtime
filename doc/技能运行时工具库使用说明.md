# 技能运行时工具库使用说明

## 一、安装

项目使用 uv 管理 Python、依赖、测试和构建：

```bash
cd /Users/zqs/PycharmProjects/AI/langchain-skill-runtime
uv sync --all-extras --dev
```

业务项目按需安装扩展：

```bash
uv add 'langchain-skill-runtime[agent,mcp]'
```

- `agent`：需要使用 `langchain.agents.create_agent` 时安装。
- `mcp`：需要连接真实 MCP Server 时安装。
- 只解析 Skill、编译 Function、脚本或客户端 Tool 时不要求安装以上扩展。

### 1.1 本机跨项目开发

另一个 uv 项目需要跟随本库源码实时更新时，使用可编辑安装：

```bash
cd /path/to/another-project
uv add --editable /Users/zqs/PycharmProjects/AI/langchain-skill-runtime
```

这种方式适合本机联调，但依赖的是绝对路径，不适合提交给其他开发者共同使用。

### 1.2 把 wheel 发给其他项目

先在本项目构建：

```bash
cd /Users/zqs/PycharmProjects/AI/langchain-skill-runtime
uv build
```

把生成的文件发送给对方：

```text
dist/langchain_skill_runtime-0.2.0-py3-none-any.whl
```

对方在自己的 uv 项目中安装：

```bash
uv add /path/to/langchain_skill_runtime-0.2.0-py3-none-any.whl
```

如果对方要使用 LangChain Agent 和真实 MCP，再安装对应扩展：

```bash
uv add 'langchain-skill-runtime[agent,mcp] @ file:///path/to/langchain_skill_runtime-0.2.0-py3-none-any.whl'
```

### 1.3 从 Git 仓库安装

把项目推送到 Git 仓库并打版本标签后，其他项目可以固定安装某个版本：

```bash
uv add 'langchain-skill-runtime @ git+https://git.example.com/ai/langchain-skill-runtime.git@v0.2.0'
```

这种方式适合团队内部共享。固定标签或提交号，避免默认分支变化影响业务项目。

### 1.4 发布到私有包仓库

团队项目较多时，建议将 wheel 发布到公司私有 Python 包仓库。发布后，业务项目的使用方式与普通依赖一致：

```bash
uv add langchain-skill-runtime==0.2.0
```

仓库地址和认证应配置在使用方的 uv 配置或 CI Secret 中，不要提交发布 Token。当前项目已经是标准 Python 包，不需要为私有仓库再修改业务代码。

## 二、核心使用流程

无论 Skill 来自文件还是数据库，流程都相同：

1. 宿主系统实现实际执行能力，例如注册 Python 函数、提供脚本执行器或客户端消息发送函数。
2. 把四类 `ToolAdapter` 注册到 `ToolFactory`。
3. 选择一种 Skill 输入方式进行编译。
4. 使用返回的 `SkillBundle.system_prompt` 和 `SkillBundle.tools` 创建 Agent。

```python
from langchain_skill_runtime import SkillRuntime
from langchain_skill_runtime.adapters import ToolFactory


tool_factory = ToolFactory(
    [
        function_adapter,
        script_adapter,
        client_adapter,
        mcp_adapter,
    ]
)

runtime = SkillRuntime(tool_factory=tool_factory)
```

`SkillRuntime` 不持有模型、数据库连接或 WebSocket 服务，只负责解析、校验、编译和结果关联。

## 三、三种 Skill 输入方式

### 3.1 直接编译 SKILL.md

适合本地目录、Git 仓库、市场下载包等不依赖数据库的场景：

```python
from pathlib import Path

from langchain_skill_runtime import SkillRuntime


runtime = SkillRuntime(tool_factory=tool_factory)
bundle = await runtime.compile_file(
    Path("skills/hotel-report/SKILL.md"),
)
```

标准的提示词型 `SKILL.md` 只需提供 `name`、`description` 和正文，此时会得到没有 Tool 的 `SkillBundle`。如果 Skill 需要工具，可以使用本库扩展的 `tools` 字段：

```yaml
---
id: hotel-report
name: hotel-report
description: 生成酒店经营日报
version: 1.0.0
allowed-tools:
  - calculate_revenue
tools:
  - id: calculate-revenue
    name: calculate_revenue
    description: 计算总营收
    type: PYTHON_FUNCTION
    input_schema:
      type: object
      properties:
        room_revenue: {type: number}
        other_revenue: {type: number}
      required: [room_revenue, other_revenue]
      additionalProperties: false
    execution:
      registry_key: hotel.calculate_revenue
---

# 酒店经营日报

计算营收后生成经营日报。
```

服务端脚本 Tool 使用相对于 `SKILL.md` 所在目录的 `execution.entry`。加载器会拒绝绝对路径和通过 `../` 逃逸 Skill 目录的路径。

### 3.2 编译业务对象

适合业务系统已经从数据库、HTTP 接口或配置中心取得数据的场景。核心库不连接数据库，也不依赖 ORM：

```python
from langchain_skill_runtime import (
    ResolvedToolDefinition,
    SkillDefinition,
    SkillRuntime,
    ToolType,
)


skill = SkillDefinition(
    id="hotel-report",
    name="hotel-report",
    description="生成酒店经营日报",
    content=skill_markdown_from_database,
    version="1.0.0",
)

tools = [
    ResolvedToolDefinition(
        id="calculate-revenue",
        name="calculate_revenue",
        description="计算总营收",
        tool_type=ToolType.PYTHON_FUNCTION,
        input_schema={
            "type": "object",
            "properties": {
                "room_revenue": {"type": "number"},
                "other_revenue": {"type": "number"},
            },
            "required": ["room_revenue", "other_revenue"],
            "additionalProperties": False,
        },
        execution_config={"registry_key": "hotel.calculate_revenue"},
        version="1.0.0",
    )
]

runtime = SkillRuntime(tool_factory=tool_factory)
bundle = await runtime.compile_objects(skill=skill, tools=tools)
```

业务系统负责先完成租户隔离、权限、启停状态和 Skill-Tool 关系查询，再把结果映射成 `SkillDefinition` 与 `ResolvedToolDefinition`。

### 3.3 按 Skill ID 使用 Repository

已有项目可以继续使用 Repository 兼容 API：

```python
runtime = SkillRuntime(
    skill_repository=BusinessSkillRepository(),
    tool_repository=BusinessToolRepository(),
    tool_factory=tool_factory,
)

bundle = await runtime.compile("hotel-report", compile_context)
```

`SkillRepository` 返回 `SkillDefinition`，`ToolRepository` 返回已经解析和授权的 `ResolvedToolDefinition`。这个入口最终也会进入与前两种方式相同的编译核心。

## 四、四类工具如何接入

### 4.1 Python Function

Python Function 必须先注册，Skill 只保存 `registry_key`，不保存或执行 Python 源码：

```python
from langchain_skill_runtime.adapters import PythonFunctionAdapter
from langchain_skill_runtime.executors import InMemoryFunctionRegistry


async def calculate_revenue(
    room_revenue: float,
    other_revenue: float,
) -> float:
    return room_revenue + other_revenue


function_registry = InMemoryFunctionRegistry()
function_registry.register("hotel.calculate_revenue", calculate_revenue)
function_adapter = PythonFunctionAdapter(function_registry)
```

### 4.2 服务端脚本

宿主系统注入 `ScriptExecutor`，生产环境应把实际执行委派给受控沙箱或任务服务：

```python
from collections.abc import Mapping
from typing import Any

from langchain_skill_runtime import CompileContext
from langchain_skill_runtime.adapters import ServerScriptAdapter


class BusinessScriptExecutor:
    async def execute(
        self,
        artifact_id: str,
        arguments: Mapping[str, Any],
        context: CompileContext,
        timeout_seconds: float,
    ) -> Any:
        return await sandbox_service.execute(
            artifact_id=artifact_id,
            arguments=dict(arguments),
            tenant_id=context.tenant_id,
            timeout_seconds=timeout_seconds,
        )


script_adapter = ServerScriptAdapter(BusinessScriptExecutor())
```

### 4.3 客户端 JavaScript Transport

客户端 Tool 在服务端创建唯一 `call_id` 并等待。宿主系统通过 WebSocket、SSE 或自有通道把请求发给客户端，再把客户端结果交回 Transport：

```python
from langchain_skill_runtime.adapters import ClientJavascriptAdapter
from langchain_skill_runtime.client import (
    ClientToolRequest,
    ClientToolResult,
    PendingClientToolTransport,
)


async def sender(request: ClientToolRequest) -> None:
    connection = connection_registry.get(request.session_id)
    await connection.send_json(request.model_dump(mode="json"))


client_transport = PendingClientToolTransport(sender=sender)
client_adapter = ClientJavascriptAdapter(client_transport)


async def on_client_result(payload: dict) -> None:
    result = ClientToolResult.model_validate(payload)
    await client_transport.accept_result(result)


async def on_client_disconnected(session_id: str) -> None:
    await client_transport.fail_session(session_id)
```

`accept_result()` 使用相同的 `call_id` 唤醒对应 Tool 调用，因此多个并发请求不会串结果。Transport 同时处理超时、断线、重复响应、迟到响应和会话/工具/版本不匹配。

客户端 Tool 需要传入当前会话和客户端已注册能力：

```python
from langchain_skill_runtime import ClientCapability, CompileContext


compile_context = CompileContext(
    session_id="client-session-1",
    client_capabilities=(
        ClientCapability(
            tool_id="client.export.file",
            version="1.0.0",
        ),
    ),
)

bundle = await runtime.compile_file(
    "skills/hotel-report/SKILL.md",
    compile_context,
)
```

### 4.4 MCP

文件型 Skill 只能声明 `server_ref`，不能直接提供 MCP URL、stdio 命令、进程参数、环境变量或 Header。宿主系统通过 `McpServerConfigProvider` 把引用解析成经过审核的连接配置，再由 `SecretProvider` 解析其中的密钥引用：

```python
from collections.abc import Mapping
from typing import Any

from langchain_skill_runtime.adapters import (
    LangChainMcpToolProvider,
    McpServerConfigProvider,
    McpToolAdapter,
)


class BusinessSecretProvider:
    async def resolve(self, reference: str, context: CompileContext) -> str:
        return await secret_service.resolve(
            tenant_id=context.tenant_id,
            reference=reference,
        )


class BusinessMcpServerConfigProvider(McpServerConfigProvider):
    async def resolve(
        self,
        reference: str,
        context: CompileContext,
    ) -> Mapping[str, Any]:
        # 只返回宿主系统已审核并预注册的配置。
        return await mcp_server_registry.get_authorized_config(
            reference=reference,
            tenant_id=context.tenant_id,
        )


mcp_adapter = McpToolAdapter(
    LangChainMcpToolProvider(
        secret_provider=BusinessSecretProvider(),
        server_config_provider=BusinessMcpServerConfigProvider(),
    )
)
```

`SKILL.md` 只保存宿主侧引用：

```yaml
execution:
  server_name: hotel-mcp
  tool_name: query_hotel_data
  server_ref: mcp/hotel
```

宿主注册表中保存的受信配置可以包含 Secret 引用：

```python
{
    "transport": "http",
    "url": "https://mcp.example.com/mcp",
    "headers": {
        "Authorization": {"secret_ref": "mcp/hotel/token"},
    },
}
```

## 五、创建 LangChain Agent

三种编译方式都返回同一种 `SkillBundle`：

```python
from langchain.agents import create_agent


agent = create_agent(
    model=business_model,
    tools=list(bundle.tools),
    system_prompt=bundle.system_prompt,
)
```

业务代码需要直接调用 Tool 时，建议按名称索引，不依赖列表位置：

```python
tools_by_name = {tool.name: tool for tool in bundle.tools}
result = await tools_by_name["calculate_revenue"].ainvoke(
    {"room_revenue": 1000, "other_revenue": 200}
)
```

## 六、完整测试 Demo

完整使用方法集中在以下一个集成测试中：

```text
tests/integration/test_library_usage.py::test_complete_library_usage
```

该测试按实际接入顺序演示：

1. 注册 Python Function。
2. 建立客户端 Transport 并按 `call_id` 回传结果。
3. 注册 Function、脚本、客户端和 MCP 四种 Adapter。
4. 分别调用 `compile_file()`、`compile_objects()` 和兼容的 `compile()`。
5. 执行四类 Tool。
6. 把 `SkillBundle` 交给 LangChain `create_agent`，验证 Agent 能发起并完成 Tool Call。

只运行完整 Demo：

```bash
uv run --all-extras pytest \
  tests/integration/test_library_usage.py::test_complete_library_usage -q
```

运行全部回归测试：

```bash
uv run --all-extras pytest -q
```

`tests` 仅存在于源码仓库，用于开发和参考，不会被打入对外发布的 wheel 或 sdist。

## 七、错误和安全边界

- 必需 Tool 构建失败时停止 Skill 编译；非必需 Tool 构建失败时跳过并写入 diagnostics。
- Prompt 只声明实际构建成功的 Tool。
- `allowed-tools` 不能创建没有 Tool 定义或数据库绑定的执行入口。
- Function 只执行 Registry 中预注册的受控函数，不使用 `eval` 或 `exec`。
- 客户端只执行预注册的 `tool_key`，服务端不临时下发 JavaScript 源码。
- 服务端脚本由外部 Executor 执行；路径型 Skill 只允许引用 Skill 根目录内的脚本。
- 文件型 Skill 的 MCP 只能使用 `server_ref`；原始连接地址、stdio 命令和凭据由宿主配置注册表控制。
- 宿主 MCP 配置中的 Secret 应只保存 `secret_ref`，解析值不进入 Prompt 和公开错误消息。
- `timeout_seconds` 对四类 Tool 统一生效。
- `output_schema` 会在结果返回 Agent 前执行校验。
- `max_output_bytes` 默认限制为 1 MiB，按 UTF-8 JSON 编码后的大小计算。
- 同一个 Skill 中启用的 Tool 名称必须唯一，并符合 LangChain Tool 名称规则。
- 未知执行异常会转换为不携带底层敏感消息的公开错误类型。
