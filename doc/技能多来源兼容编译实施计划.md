# 技能多来源兼容编译实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不破坏现有 Repository API 的前提下，为工具库增加 `SKILL.md` 文件编译和数据库对象直接编译能力，并提供一个完整、可阅读的库使用测试 Demo。

**Architecture:** 三种公共入口 `compile_file()`、`compile_objects()` 和现有 `compile()` 统一转换为 `SkillDocument`，再进入唯一的 `_compile_document()` 编译核心。文件读取与 Frontmatter Tool 规范化由独立 `SkillFileLoader` 完成，ToolFactory、Adapter、执行保护和 PromptCompiler 保持来源无关。

**Tech Stack:** Python 3.11+、uv、Pydantic 2、PyYAML、JSON Schema Draft 2020-12、LangChain Core、pytest、pytest-asyncio、Ruff、Mypy。

## 全局约束

- 目标版本为 `0.2.0`。
- 核心库不连接数据库，也不依赖 ORM。
- `compile()`、Repository Protocol 和现有 ToolAdapter API 保持兼容。
- `SKILL.md` 的 `tools` 是文件模式唯一可执行 Tool 来源；`allowed-tools` 仅用于兼容诊断。
- 不执行 Frontmatter 内嵌源码，不允许脚本路径逃逸 Skill 根目录。
- Function、脚本、客户端和 MCP 四类 Tool 共用当前超时、输出校验和安全异常规则。
- 文档使用中文命名并仅放在 `doc/`；本功能不新增 SQL。
- `tests/`、测试 Skill 和测试 MCP Server 不进入 wheel 或源码分发包。
- 保留安全回归单元测试，只删除没有断言或被完整使用 Demo 覆盖的重复测试。
